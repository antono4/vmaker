Modes

Pick a mode in the UI. Each one maps to the task name H3 expects and to its own condition set.

Text to Video

t2va

A clip generated from a description alone, with score and ambience.

Inputs
prompt only
Makes
video + stereo audio

Image to Video

fl2va

Animation anchored to one image, or bracketed by a first and a last frame.

Inputs
1 or 2 images
Roles
keyframe, first / last

Reference to Video

ref2va

Reuses subjects, style, motion and voice from a pool of supplied media.

Inputs
9 img, 3 vid, 3 aud
Roles
reference

Backends

One adapter interface, three ways to render. The UI only offers the ones usable in your environment.

1Demo renderer

A CPU renderer that produces a real, playable, watermarked mp4 with stereo audio. No GPU and no credentials, so the whole flow works on first launch. It is never model output.

Needs
nothing

2Local H3 server

The official self-hosting path through SGLang or vLLM. Ref2VA runs on a second server on its own port, because it uses a different variant.

Needs
CUDA GPU, ~24 GB VRAM at 768p
Weights
~85 GB download

3MiniMax Open Platform

Hosted generation with no GPU. It also unlocks the two hosted-only extras in the UI: prompt expansion and 2K regeneration.

Needs
an API key
Extras
expand prompt, regenerate 2K

Prompting

H3 takes a structured description, and the quality difference is large. The composer builds it from form fields and previews the result live. 

# t2va and fl2va emit three sections
integrated_multimodal_description: realistic photographic,
cinematic, 35mm film. The scene is set in a rain soaked Tokyo alley
at night. Lighting: warm golden hour backlight, soft shadows.
[Shot 1] medium shot. The camera pushes in slow, steady. A lone
cyclist pedals toward the camera, splashing through puddles.
overall_soundscape: A low ambient hum, tyres hissing over wet
asphalt, a distant tram bell, water dripping from an awning.
non_diegetic_music: A sparse solo piano motif over warm
sustained strings, slow tempo, resolving softly.

Ref2VA emits six sections in a fixed order: subject_definitions, summary, retention_analysis, detailed_description, overall_soundscape, non_diegetic_music.

  • Shot timestamps only from shot 2 onward, formatted At 00:04.500,
  • Camera written as motion, amplitude and speed, never as bare "zooms in"
  • Dialogue wrapped in <d>[lang] … </d> so the speaker is spoken
  • Reference labels keep one meaning across all six sections
  • Retention analysis notes which shots use a label, with the guide's vocabulary

The two official guides ship with the repo under docs/, and docs/PROMPTING.md maps each rule to the code that enforces it.

Quick start

Clone, run, open. The first launch installs dependencies and starts on the demo backend.

# clone and run
git clone https://github.com/antono4/vmaker
cd vmaker
./run.sh
# open http://127.0.0.1:12000

Real generation needs a GPU and the H3 weights, or a MiniMax API key. See the README for the SGLang and vLLM setup. 

# real generation, no GPU
export MINIMAX_API_KEY=...
export MINIMAX_API_BASE=https://api.minimax.io
./run.sh

# self-hosted on a CUDA GPU
./tools/download_model.sh
./tools/serve_local.sh --model-path ./models/MiniMax-H3

Verified behaviour

What was actually measured on a running instance, rather than assumed from the model card.

  • Audio is real stereo, not a duplicated mono channel: AAC at 32 kHz with distinct left and right content
  • Sizing follows the short edge: 16:9 gives 1364×768, 9:16 gives 768×1364, encoded at 24 fps
  • All three modes complete end to end through the browser UI and the HTTP API
  • Cancellation is cooperative, so Delete stops a render in flight and shutdown drains cleanly
  • 51 tests pass, driving the real ASGI app and writing real media files, with nothing mocked
